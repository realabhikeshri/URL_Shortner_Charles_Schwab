# Engineering summary

## 1. Plan and rationale

The assignment asks for an agentic SDLC orchestrator that is governed, resumable and auditable, demonstrated on a
real service. The plan was **engine first, then use it to build the product**:

1. A small purpose-built engine (ADR-001) with a persisted per-node state machine, because governance (gates,
   policies, approvals, rollback, re-planning, audit) is the thing being evaluated and must be unit-testable.
2. Agents behind a provider interface with an **offline deterministic default** (ADR-003): the demo, CI and the
   evidence in `runs/` are reproducible, while Claude can drive the same agents.
3. Three scenarios chained on one workspace: greenfield → brownfield (impact analysis, red-first test, retry,
   rollback, migration approval) → ambiguous (clarification, mid-run change, re-plan, high-risk gates).
4. The service in `service/` is **not hand-written into the repo**: it is synced from orchestrator output and
   verified byte-identical (`make verify-lineage`, an end-to-end test). Review findings were fixed in the
   blueprints and the runs re-executed (ADR-014).

## 3. Risks, trade-offs, validation

- **Trade-off:** a deterministic provider buys reproducibility and an honest offline demo at the cost of generality
  (LIMITATIONS 1). The Anthropic provider exists and is unit-tested but was not run live (LIMITATIONS 2).
- **Trade-off:** one shared workspace with disjoint write sets instead of a worktree per node (ADR-015).
- **Validation:** 285 tests, service coverage 97%, orchestrator 91%, mypy --strict, ruff, bandit, pip-audit clean;
  3 committed runs with intact audit chains; byte-identical lineage; Docker compose smoke test on Postgres 16 +
  Redis 7; load check p95 6 ms vs 50 ms target. Bugs found by running the system are listed in BUILD_LOG.md.
- Full register: `RISKS.md`; threat model: `SECURITY.md`.

## 4. Assumptions and limitations

See `ASSUMPTIONS.md` (18 items) and `LIMITATIONS.md`. The most important: scripted fault/mid-run change for
reproducibility, local-only approvals identity, un-run CI workflow, deterministic provider scope.
